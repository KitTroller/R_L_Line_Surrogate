Your three confusions, in order

1 · "How do I do this without an integrator?"

You stop stepping through time. That is the whole answer. Compare what you wrote for the PLL against what you will write here:

PLL — forward

theta = torch.zeros(n, N)
for k in range(1, N):            # 5000 steps
    th, om, vd, vq = \
      self._integrator_step_trapezoid(
        theta[:,k-1], omega[:,k-1],
        Vq[:,k-1], Va[:,k], Vb[:,k], Vc[:,k])
    # ... and a Newton loop inside
    theta[:,k] = th

Line — backward

i    = A*cos(th) + B*h           # (n, S) at once
didt = A*r*cos(th) - A*wg*sin(th) - (B/tau)*h
dv   = ell*didt + R*i

# no k, no loop, no Newton, no tolerance

Three array expressions evaluated on the whole time grid simultaneously. There is nothing to iterate because you never solve anything — you differentiate, and differentiation of a formula you wrote down yourself is just more formula.

The one rule

Write didt out by hand from calculus. Never np.gradient, never torch.diff. Finite differences amplify error by 1/dt = 10⁴ at dt = 100 µs; in float32 that is 1.2e-3 of noise sitting on an envelope signal of 4.4e-4 — nearly 3× larger than the thing you are trying to learn. Analytic derivative, and float64.

Wang & Perdikaris hit this exact wall in §4.1 and their fix is equation 4.11: two branch networks, one for the forcing function, one for the initial condition. You already do the same thing without noticing — your branch is [sin θ₀, cos θ₀, ω₀, Va, Vb, Vc], which is three IC scalars concatenated with three sampled functions.

So: env_rate is a property of the current profile, not a state. Concretely it is one number r in units of 1/s, and the amplitude is A(t) = I₀·exp(r·t):

3 · "What is the fault severity dimension?"

Delete it for now

Your supervisor just told you to: "I suggest we start with the steady-state case and then add the decaying/increasing currents later." Stage A has no fault axis and no envelope axis at all — r = 0 everywhere. When his profiles arrive, a fault is nothing more exotic than a large negative r applied over part of the window. One number, same code path.

B

Train on windows, not trajectories

Changes the whole file

This is the piece that makes everything downstream simple, and it is a freedom you only get because you are generating backwards.

In PLL_Attempt you had no choice: forward integration produces a trajectory, so you simulated 0.5 s and chopped it into W windows with unfold. Every window's i₀ was whatever the previous window happened to end at.

Backwards, nothing forces that. You can write down a valid (i₀, Δv, i) triple on a bare 12.5 ms grid without any trajectory existing around it. So sample each training window independently, with its own i₀ drawn as wide as you like.

Three things fall out of this, and all three make your life easier:

  • No unfold, no check_continuity, no global horizon in the training generator. It emits (n_samples, S) arrays on a bare t_local grid.
  • W and T stop being training decisions. You pick S (window length in samples) and that is the only geometry the operator ever sees. W is now purely "how many times do I chain it at deployment".
  • The i₀ distribution becomes yours to choose, so you can deliberately make it wider than the rollout drift — which is the fix for the compounding problem your PLL notes spent F32/F45/F46 chasing.

You still generate trajectories, just in a second, much smaller function used only by rollout_metrics. Same profile() call, longer time grid.

C

Why a steady-state dataset needs one extra term

Do not skip

Take "steady state" completely literally — pure sinusoid, nothing else — and the dataset is quietly broken. If every current is exactly the steady-state response to its own Δv, then i₀ is a deterministic function of Δv. It carries no independent information, the network learns to ignore it, and at rollout, when your own prediction error nudges i₀ off the manifold, there is no mechanism to respond. You would have built a windowed regressor and called it a recurrent operator.

Fix: add the homogeneous mode to the current you prescribe.

i(t) = A(t)·cos(ω_g t + φ) + B·e^(−t/τ) └─ this term

Push it through Δv = ℓ·di/dt + R·i. The B term contributes B·e^(−t/τ)·(−ℓ/τ + R), and since τ ≡ ℓ/R that bracket is exactly zero.

What that means

B changes i without changing Δv at all. One Δv corresponds to a whole one-parameter family of currents, and i₀ is the only thing that tells them apart. That is what makes the branch's i₀ input load-bearing rather than decorative — and it is the same one-dimensional null space {c·e^(−t/τ)} from the physics-loss argument, showing up here as a data-design tool.

It is also a free unit test: generate twice with different B, same everything else, and Δv must come back bit-identical.

Sample it relative to the amplitude — B = beta · I0 with beta ∈ [−0.3, 0.3] — so a small current never ends up dominated by a decaying DC offset it could not physically have.

1.2 · line_ODEs and delta_v — the same equation, twice

Generation only calls delta_v. But line_ODEs is what your residual and your round-trip test need — keep it, and keep them algebraically consistent.
    def line_ODEs(self, Ic, Delta_V):
        """Forward form. Generation never calls this; the residual and the
        round-trip test do. NOTE: divide by ell, not by X."""
        return (Delta_V - self.R * Ic) / self.ell

    def delta_v(self, Ic, dIc_dt):
        """Inverse form. This one line is the entire flip."""
        return self.ell * dIc_dt + self.R * Ic

That is genuinely all of it. Your current line_ODEs divides by Lc; it must be ell, which is a factor of 314 different.

Two methods that are the same constraint ℓ·di/dt + R·i = Δv rearranged for each unknown. They must be exact inverses of each other: line_ODEs(i, delta_v(i, d)) == d to machine precision, for random i and d.

The maths, once, so you can check the code against it:

A(t) = I₀·e^(r t) θ(t) = ω_g t + φ h(t) = e^(−t/τ) i = A·cos θ + B·h di/dt = r·A·cos θ − A·ω_g·sin θ − (B/τ)·h └ dA/dt ┘ └── chain rule ──┘ └─ dh/dt ─┘ 
class Line_Simulator:
    def __init__(self, physics=None, S=125, dt=1e-4):
        self.physics = physics or Line_Physics()     # NOT a local variable
        self.S  = S
        self.dt = dt
        self.t  = (torch.arange(S) * dt).reshape(1, S)          # (1, S)

    def profile(self, I0, phi, freq_offset, env_rate, B):
        """All params (n,1). Returns i, didt each (n,S)."""
        ph      = self.physics
        t       = self.t
        omega_g = ph.omega_0 + 2 * torch.pi * freq_offset       # (n,1)
        th      = omega_g * t + phi                             # (n,1)*(1,S) -> (n,S)
        A       = I0 * torch.exp(env_rate * t)                  # (n,S)
        h       = torch.exp(-t / ph.tau)                        # (1,S)

        i    = A * torch.cos(th) + B * h
        didt = (A * env_rate) * torch.cos(th) \
             - A * omega_g * torch.sin(th) \
             - (B / ph.tau) * h
        return i, didt

    def batch(self, I0, phi, freq_offset, env_rate, B):
        i, didt = self.profile(I0, phi, freq_offset, env_rate, B)
        return i, self.physics.delta_v(i, didt)

Note omega_g * t is a broadcast, not a matrix product — the same thing your _grid_phases docstring warns about.

One phase, not three

The three-phase system is diagonal, so phases b and c are phase a with φ ∓ 2π/3 — and you are already sampling φ uniformly over the full circle. Generating three phases would give you three copies of a distribution you already have. Generate one scalar channel: branch = [i₀, Δv(S)], S + 1 inputs, output_dim = 1. The three phases come back at rung 2, when the Park transform couples them, and cost one line then.

class Line_Dataset:
    COLUMNS = ["I0", "phi", "freq_offset", "env_rate", "beta"]

    def __init__(self, cfg, seed=None):
        self._rng = np.random.default_rng(seed)
        self.n    = cfg.n_samples
        self.sim  = Line_Simulator(S=cfg.S, dt=cfg.dt)
        self.cfg  = cfg

    def _lhs(self, d, n):
        return LatinHypercube(d=d, seed=self._rng).random(n)

    def sample_params(self):
        u  = torch.as_tensor(self._lhs(5, self.n))     # (n,5) in [0,1)
        r  = self.cfg.ranges
        col = lambda k, j: (r[k][0] + (r[k][1] - r[k][0]) * u[:, j]).reshape(-1, 1)

        phi         = col("phi", 1)
        freq_offset = col("freq_offset", 2)
        env_rate    = col("env_rate", 3)               # [0,0] in stage A

        return I0, phi, freq_offset, env_rate, B

        # reshape every one to (n,1)
        # B = beta * I0   (NOT an independent absolute draw)
        return I0, phi, freq_offset, env_rate, B

The four tests that make this bulletproof

Run each one the moment the function it covers exists. All four are cheap and all four are decisive — this is the payoff for choosing a system with an exact solution.

#testhowmust return
T1 Inverse pair Random i, random d. Check line_ODEs(i, delta_v(i, d)) == d. < 1e-15
T2 B cancellation Generate with beta = 0 and beta = 0.3, everything else fixed. Compare Δv. exactly 0
T3 Phasor env_rate = 0, B = 0. Take peak of Δv over peak of i, and the phase lead. 0.100125 pu
87.138°
T4 Round trip Feed Δv to scipy.integrate.solve_ivp with line_ODEs, rtol=atol=1e-12, starting from i[0]. Compare against i. < 1e-10

T2 is the one to write first — it is two lines, it needs no reference solution, and it catches a wrong τ, a wrong ℓ, and a sign error in didt all at once. T4 is the one that matters: it is the test PLL_Attempt could never run, and passing it means your generator is correct in an absolute sense, not merely self-consistent.

If T4 fails by a factor near 314

Something is still dividing by X where it should divide by ell. That is ω_b = 314.159, and it has now been the cause of every unit problem in this project.

4

The three dataset stages

Your supervisor's staging, made concrete. Each stage is a config edit, not a rewrite — which is the reason to keep the env_rate column in Stage A even though it is pinned at zero.

stagewhat changesenv_rate rangegate to move on
A steady sinusoid + homogeneous mode [0, 0] all four tests pass; training reaches far below anything in PLL_Attempt
B slow envelope — "half or double in 0.5 s" [−1.386, +1.386] error does not degrade vs A; the in-phase term is now being learned
C faults — fast forced decay, from his profiles down to −460 report clean vs fault separately, the way F32 splits clean / sag / jump

One thing to expect at Stage C, so it does not surprise you: in steady state the in-phase part of Δv is 5% of the quadrature part, and the envelope contributes 0.44%. During a 5 ms forced decay the in-phase part becomes −0.1416 — 82% of the quadrature, and with the opposite sign. The regime where the dynamics are nearly invisible and the regime where they dominate are the same dataset. That is a good argument for reporting them separately from the very first run.

Two scaling decisions the PLL got for free

Δv is ~0.1 pu, not ~1. The PLL fed Va/Vb/Vc in raw at nominal 1 pu. Feeding a 0.1-scale signal into a tanh stack wastes most of the activation range — normalise the branch function by its own std, or by |Z|, which is the physically meaningful choice since Δv/|Z| ≈ i.

t ∈ [0, 0.0125] is a tiny trunk input. Feed the raw channel as t/T_window in [0, 1] (or [−1, 1]) and keep the Fourier features on physical t so max_freq keeps its rad/s meaning. This may be part of why F31 measured a 4.16× gain from Fourier features — the raw channel alone was badly scaled.

            self.trunk_sizes[-1]  = self.hidden_dim
            self.branch_sizes[-1] = self.hidden_dim * self.output_dim

        self.trunk_net  = MLP(self.trunk_sizes)
        self.branch_net = MLP(self.branch_sizes)

    def config(self):
        return {"arch": "Line_DeepONet", "hidden_dim": self.hidden_dim,
                "output_dim": self.output_dim, "F": self.F, "max_freq": self.max_freq,
                "trunk_sizes": self.trunk_sizes, "branch_sizes": self.branch_sizes}

    def forward(self, branch_input, trunk_input):
        B, T, _ = trunk_input.shape
        b = self.branch_net(branch_input).view(B, self.output_dim, self.hidden_dim)
        t = self.trunk_net(trunk_input).view(B, T, self.hidden_dim)
        return torch.einsum('boh,bth->bot', b, t).transpose(1, 2)   # (B,T,O)

S_win comes from meta["S"] at construction, not from the YAML — the same discipline as train_pll.main, so a dataset and a model can never silently disagree about window length.

5.4 · What the einsum actually does

Worth being able to say out loud, because it is the reason a linear operator is exactly representable here (§01 of the guide, row three).

G(u)(t) = Σ_h b_h(u) · τ_h(t) └ branch ┘ └ trunk ┘ branch (B, O, H) ⊗ trunk (B, T, H) → (B, O, T)

The branch turns the whole input function into H coefficients; the trunk turns each query time into H basis values; the output is their inner product. That is a finite-rank expansion — and the exact solution operator of your line, i(t) = i₀·e^(−t/τ) + (1/ℓ)∫₀ᵗ e^(−(t−s)/τ)·Δv(s) ds, is linear in (i₀, Δv), so a rank-H expansion can represent it exactly. Any error you measure is therefore an optimisation failure, not an approximation one.

def compute_i(model, t_query, branch, delta_v, physics):
    """physics: ell*di/dt + R*i = delta_v   ->   di/dt + i/tau - delta_v/ell = 0"""
    trunk = build_trunk_input(t_query, model.F, model.max_freq)
    i     = model.forward(branch, trunk)                    # (B,T,1)
    didt  = torch.autograd.grad(i, t_query, torch.ones_like(i),
                                create_graph=True)[0]
    res   = didt + i / physics.t_constant - delta_v / physics.Lc
    return {"i": i, "didt": didt, "res": res}

Evaluate the operator at the query points, differentiate the output with respect to those points with the graph retained, and return the ODE written as a single residual. The forcing is read from the dataset and treated as constant with respect to the network output.

Why this residual is provably Sobolev supervision

In the PLL you inferred F13 from the fact that the residual moved 10% while deployed error moved 2.4×. Here it is one line of algebra. The true solution satisfies Δv/ℓ = di/dt|true + i_true/τ exactly. Substitute that into the residual:

res = ( di/dt|pred − di/dt|true ) + ( i_pred − i_true ) / τ └──── derivative error ────┘ └── data error ──┘ × 15.7

The physics loss is the derivative error plus 1/τ times the value error — not approximately, exactly. So it is a Sobolev penalty with a known, computable mixing weight. That also tells you its null space directly: res = 0 for any error of the form c·e^(−t/τ), one dimension, decaying.

6.3 · Scales, and a free extra label

Normalise the residual by the RMS of the terms it is built from, exactly as s1/s2 do in train_pll.main — otherwise a dimensionless w_phys means nothing:

s = (delta_v / ell - i / tau).pow(2).mean().sqrt().item()   # = RMS(di/dt), ~222 pu/s
...
r = (out["res"] / s).pow(2).mean()

One scale, computed once on the training split from the dataset's own Δv and i: the RMS of the equation's right-hand side. Divide the residual by it before squaring.

An experiment you could not run on the PLL

Your generator computes didt exactly and throws it away. Store it in the npz and you have a direct derivative label, which by the algebra above is almost the same information the physics term supplies. That gives you two ways to inject it:

  • w_phys · ‖res/s‖² — the physics route
  • w_d · ‖di/dt|pred − di/dt|true‖² — the label route

They differ only by the 1/τ value-error term. Comparing them is a cheap, clean ablation that turns F13 from an interpretation into a measurement. Worth one column in the sweep.

6.4 · Test T5 — the one this whole rung exists for

Wrap the exact solution in a module with the operator's interface and push it through compute_i. If the residual does not come back at machine zero, something in the autograd path, the sign, ℓ, τ or the trunk layout is wrong — and you find it in seconds instead of after a training run.

class _Exact(torch.nn.Module):
    """Pretends to be the trained operator, returns the closed form."""
    F, max_freq, output_dim = 0, 0, 1          # F=0 -> trunk is raw t, channel 0
    def __init__(self, I, phi, r, B, wg, tau):
        super().__init__(); self.p = (I, phi, r, B, wg, tau)
    def forward(self, branch, trunk):
        I, phi, r, B, wg, tau = self.p
        t = trunk[..., 0:1]
        return I*torch.exp(r*t)*torch.cos(wg*t + phi) + B*torch.exp(-t/tau)

# then
res = compute_i(_Exact(...), t_query, branch, delta_v, physics)["res"]
assert res.abs().max() < 1e-10

A stand-in module exposing F, max_freq, output_dim and forward(branch, trunk), returning the analytic current evaluated at the trunk's raw time channel. Passed through compute_i against the matching Δv, the residual must be machine zero.

Two ways to fail T5 that look identical

A residual around 1e-4 relative means ℓ and τ are consistent but the derivative is off by truncation — check you are not differentiating numerically anywhere. A residual around 314× too large means an ω_b is missing again. And a residual that is exactly 2·R·B·h/ℓ means the B sign is back.

    def fit(self):
        best, best_state, best_ep, bad = float("inf"), None, -1, 0
        self.history = {"train": [], "val": []}
        self.status  = "ok"
        for ep in range(1, self.cfg.epochs + 1):
            trm = self._epoch(self.tr, True)
            vam = self._epoch(self.va, False)
            if not np.isfinite(vam["total"]) or (ep > 3 and vam["total"] > 50 * best):
                self.status = "diverged"; break
            self.history["train"].append(trm); self.history["val"].append(vam)
            self.sched.step(vam["total"])
            if vam["total"] < best - 1e-9:
                best, best_ep, bad = vam["total"], ep, 0
                best_state = {k: v.detach().clone()
                              for k, v in self.model.state_dict().items()}
            else:
                bad += 1
                if bad >= self.cfg.patience: break
        if best_state is not None:
            self.model.load_state_dict(best_state)       # always evaluate the BEST
        self.best_epoch = best_ep
        return self.status

9.2 · rollout — where the operator becomes an integrator

This is the deployment mode: predict window 0, take your own prediction at the boundary as window 1's initial condition, repeat W times, then compare the stitched result against the true 0.5 s trajectory. One function does both arms: feedback=True chains its own predictions, feedback=False hands every window its true i₀ (teacher forcing).

Corrected — the handover is at t = S·dt, not at the last sample

An earlier version of this section handed over i_hat[:, -1]. That is the prediction at t = (S−1)·dt, one dt before the next window starts. On a 50 Hz carrier that is a slope error of ~ω·A·dt ≈ 1.9e-2 pu at every boundary. Measured on the same trained model: compounding 6.6× with the old handover, 1.57× with the correct one.

The fix is the t_ext trick from pll_infer.py: query the trunk at the S sensor times plus t = S·dt, hand over that extra point, and drop it before stitching. The trunk is continuous in t, so this costs one extra query point.

And the older trap still applies: the handed-forward i₀ must be re-normalised with the checkpoint's own i0_mean / i0_s_deviation before it re-enters the branch.

@torch.no_grad()
def rollout(model, ck, traj, W, feedback=True, device="cpu"):
    t = ck["t_local"]
    S = t.shape[0]
    t_ext = torch.cat([t, t[-1:] + (t[1] - t[0])]).view(1, S + 1, 1)  # + the NEXT window's t=0
    dv      = traj["delta_v"].float().view(-1, W, S).to(device)       # rows ordered (run, segment)
    i0_true = traj["i0"].float().view(-1, W).to(device)
    R = dv.shape[0]
    trunk = build_ff_trunk_input(t_ext.expand(R, -1, -1), model.F, model.max_freq)
    mu, sd, sd_dv = float(ck["i0_mean"]), float(ck["i0_s_deviation"]), float(ck["s_deviation_dv"])

    i0, preds = i0_true[:, 0], []
    for w in range(W):
        if not feedback:
            i0 = i0_true[:, w]                         # teacher forcing
        branch = torch.cat([((i0 - mu) / sd).unsqueeze(-1), dv[:, w] / sd_dv], dim=-1)
        i_hat = model(branch, trunk)[..., 0]           # (R, S+1)
        preds.append(i_hat[:, :S])                     # drop the boundary point
        i0 = i_hat[:, S]                               # <-- AT the next window's t=0
    return torch.stack(preds, dim=1)                   # (R, W, S)

Load defaults, merge command-line overrides, expand any list-valued key into the cartesian product of runs, and hand each resulting config to the trainer. A single run and a sweep must go through identical code.

10.2 · cli_dataset.py — one job

Make the seed non-optional

Your PLL metadata carries "lhs_seed": None annotated "None = pre-2026-08-21, UNREPRODUCIBLE". That is a whole family of datasets that can never be regenerated. A CLI that refuses to run without seed= makes it impossible to repeat.

if __name__ == "__main__":
    cli = OmegaConf.from_cli()
    if "seed" not in cli:
        sys.exit("refusing to build an unreproducible dataset: pass seed=<int>")
    g = Dataset_Generator(seed=int(cli.seed))
    rec, meta = g.build_training_set()
    g.save_dataset(rec, meta, cli.get("out", "line_stageA.npz"))
    # the eval trajectories get a DIFFERENT seed -- genuinely held out
    tr = g_eval = Dataset_Generator(seed=int(cli.seed) + 10_000).build_trajectories()
    ...

Parse key=value arguments, refuse to proceed without an explicit seed, build the training set and the trajectory set — the latter with a different seed so it is genuinely held out — and write both with their metadata.

10.3 · The record schema

One JSON per run in sweeps/, written atomically (tmp.write_text(...) then tmp.replace(p)) so a killed HPC job never leaves a half-file. Everything downstream reads this.

Note S, not W. Window length is now a property of the training data and W is a deployment choice, so the tag names the thing that actually varied. That is the one place this project's file naming genuinely diverges from the PLL's, and it follows directly from §B.
