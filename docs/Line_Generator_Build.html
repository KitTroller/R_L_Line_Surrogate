1 · "How do I do this without an integrator?"

You stop stepping through time. That is the whole answer. Compare what you wrote for the PLL against what you will write here:

PLL — forward

theta = torch.zeros(n, N)
for k in range(1, N):            # 5000 steps
    th, om, vd, vq = \
      self._integrator_step_trapezoid(
        theta[:,k-1], omega[:,k-1],
        Vq[:,k-1], Va[:,k], Vb[:,k], Vc[:,k])
    # ... and a Newton loop inside
    theta[:,k] = th

Line — backward

i    = A*cos(th) + B*h           # (n, S) at once
didt = A*r*cos(th) - A*wg*sin(th) - (B/tau)*h
dv   = ell*didt + R*i

# no k, no loop, no Newton, no tolerance

Three array expressions evaluated on the whole time grid simultaneously. There is nothing to iterate because you never solve anything — you differentiate, and differentiation of a formula you wrote down yourself is just more formula.

The one rule

Write didt out by hand from calculus. Never np.gradient, never torch.diff. Finite differences amplify error by 1/dt = 10⁴ at dt = 100 µs; in float32 that is 1.2e-3 of noise sitting on an envelope signal of 4.4e-4 — nearly 3× larger than the thing you are trying to learn. Analytic derivative, and float64.

B

Train on windows, not trajectories

Changes the whole file

This is the piece that makes everything downstream simple, and it is a freedom you only get because you are generating backwards.

In PLL_Attempt you had no choice: forward integration produces a trajectory, so you simulated 0.5 s and chopped it into W windows with unfold. Every window's i₀ was whatever the previous window happened to end at.

Backwards, nothing forces that. You can write down a valid (i₀, Δv, i) triple on a bare 12.5 ms grid without any trajectory existing around it. So sample each training window independently, with its own i₀ drawn as wide as you like.

Three things fall out of this, and all three make your life easier:

  • No unfold, no check_continuity, no global horizon in the training generator. It emits (n_samples, S) arrays on a bare t_local grid.
  • W and T stop being training decisions. You pick S (window length in samples) and that is the only geometry the operator ever sees. W is now purely "how many times do I chain it at deployment".
  • The i₀ distribution becomes yours to choose, so you can deliberately make it wider than the rollout drift — which is the fix for the compounding problem your PLL notes spent F32/F45/F46 chasing.

You still generate trajectories, just in a second, much smaller function used only by rollout_metrics. Same profile() call, longer time grid.

C

Why a steady-state dataset needs one extra term

Do not skip

Take "steady state" completely literally — pure sinusoid, nothing else — and the dataset is quietly broken. If every current is exactly the steady-state response to its own Δv, then i₀ is a deterministic function of Δv. It carries no independent information, the network learns to ignore it, and at rollout, when your own prediction error nudges i₀ off the manifold, there is no mechanism to respond. You would have built a windowed regressor and called it a recurrent operator.

Fix: add the homogeneous mode to the current you prescribe.

i(t) = A(t)·cos(ω_g t + φ) + B·e^(−t/τ) └─ this term

Push it through Δv = ℓ·di/dt + R·i. The B term contributes B·e^(−t/τ)·(−ℓ/τ + R), and since τ ≡ ℓ/R that bracket is exactly zero.

What that means

B changes i without changing Δv at all. One Δv corresponds to a whole one-parameter family of currents, and i₀ is the only thing that tells them apart. That is what makes the branch's i₀ input load-bearing rather than decorative — and it is the same one-dimensional null space {c·e^(−t/τ)} from the physics-loss argument, showing up here as a data-design tool.

It is also a free unit test: generate twice with different B, same everything else, and Δv must come back bit-identical.

Sample it relative to the amplitude — B = beta · I0 with beta ∈ [−0.3, 0.3] — so a small current never ends up dominated by a decaying DC offset it could not physically have.

class Line_Simulator:
    def __init__(self, physics=None, S=125, dt=1e-4):
        self.physics = physics or Line_Physics()     # NOT a local variable
        self.S  = S
        self.dt = dt
        self.t  = (torch.arange(S) * dt).reshape(1, S)          # (1, S)

    def profile(self, I0, phi, freq_offset, env_rate, B):
        """All params (n,1). Returns i, didt each (n,S)."""
        ph      = self.physics
        t       = self.t
        omega_g = ph.omega_0 + 2 * torch.pi * freq_offset       # (n,1)
        th      = omega_g * t + phi                             # (n,1)*(1,S) -> (n,S)
        A       = I0 * torch.exp(env_rate * t)                  # (n,S)
        h       = torch.exp(-t / ph.tau)                        # (1,S)

        i    = A * torch.cos(th) + B * h
        didt = (A * env_rate) * torch.cos(th) \
             - A * omega_g * torch.sin(th) \
             - (B / ph.tau) * h
        return i, didt

    def batch(self, I0, phi, freq_offset, env_rate, B):
        i, didt = self.profile(I0, phi, freq_offset, env_rate, B)
        return i, self.physics.delta_v(i, didt)

Note omega_g * t is a broadcast, not a matrix product — the same thing your _grid_phases docstring warns about.

One phase, not three

The three-phase system is diagonal, so phases b and c are phase a with φ ∓ 2π/3 — and you are already sampling φ uniformly over the full circle. Generating three phases would give you three copies of a distribution you already have. Generate one scalar channel: branch = [i₀, Δv(S)], S + 1 inputs, output_dim = 1. The three phases come back at rung 2, when the Park transform couples them, and cost one line then.

Two scaling decisions the PLL got for free

Δv is ~0.1 pu, not ~1. The PLL fed Va/Vb/Vc in raw at nominal 1 pu. Feeding a 0.1-scale signal into a tanh stack wastes most of the activation range — normalise the branch function by its own std, or by |Z|, which is the physically meaningful choice since Δv/|Z| ≈ i.

t ∈ [0, 0.0125] is a tiny trunk input. Feed the raw channel as t/T_window in [0, 1] (or [−1, 1]) and keep the Fourier features on physical t so max_freq keeps its rad/s meaning. This may be part of why F31 measured a 4.16× gain from Fourier features — the raw channel alone was badly scaled.

                "output_dim": self.output_dim, "F": self.F, "max_freq": self.max_freq,
                "trunk_sizes": self.trunk_sizes, "branch_sizes": self.branch_sizes}

    def forward(self, branch_input, trunk_input):
        B, T, _ = trunk_input.shape
        b = self.branch_net(branch_input).view(B, self.output_dim, self.hidden_dim)
        t = self.trunk_net(trunk_input).view(B, T, self.hidden_dim)
        return torch.einsum('boh,bth->bot', b, t).transpose(1, 2)   # (B,T,O)

5.4 · What the einsum actually does

Worth being able to say out loud, because it is the reason a linear operator is exactly representable here (§01 of the guide, row three).

G(u)(t) = Σ_h b_h(u) · τ_h(t) └ branch ┘ └ trunk ┘ branch (B, O, H) ⊗ trunk (B, T, H) → (B, O, T)

The branch turns the whole input function into H coefficients; the trunk turns each query time into H basis values; the output is their inner product. That is a finite-rank expansion — and the exact solution operator of your line, i(t) = i₀·e^(−t/τ) + (1/ℓ)∫₀ᵗ e^(−(t−s)/τ)·Δv(s) ds, is linear in (i₀, Δv), so a rank-H expansion can represent it exactly. Any error you measure is therefore an optimisation failure, not an approximation one.

Evaluate the operator at the query points, differentiate the output with respect to those points with the graph retained, and return the ODE written as a single residual. The forcing is read from the dataset and treated as constant with respect to the network output.

Why this residual is provably Sobolev supervision

In the PLL you inferred F13 from the fact that the residual moved 10% while deployed error moved 2.4×. Here it is one line of algebra. The true solution satisfies Δv/ℓ = di/dt|true + i_true/τ exactly. Substitute that into the residual:

res = ( di/dt|pred − di/dt|true ) + ( i_pred − i_true ) / τ └──── derivative error ────┘ └── data error ──┘ × 15.7

The physics loss is the derivative error plus 1/τ times the value error — not approximately, exactly. So it is a Sobolev penalty with a known, computable mixing weight. That also tells you its null space directly: res = 0 for any error of the form c·e^(−t/τ), one dimension, decaying.

6.3 · Scales, and a free extra label

Normalise the residual by the RMS of the terms it is built from, exactly as s1/s2 do in train_pll.main — otherwise a dimensionless w_phys means nothing:

s = (delta_v / ell - i / tau).pow(2).mean().sqrt().item()   # = RMS(di/dt), ~222 pu/s
...
r = (out["res"] / s).pow(2).mean()

One scale, computed once on the training split from the dataset's own Δv and i: the RMS of the equation's right-hand side. Divide the residual by it before squaring.

An experiment you could not run on the PLL

Your generator computes didt exactly and throws it away. Store it in the npz and you have a direct derivative label, which by the algebra above is almost the same information the physics term supplies. That gives you two ways to inject it:

  • w_phys · ‖res/s‖² — the physics route
  • w_d · ‖di/dt|pred − di/dt|true‖² — the label route

They differ only by the 1/τ value-error term. Comparing them is a cheap, clean ablation that turns F13 from an interpretation into a measurement. Worth one column in the sweep.

6.4 · Test T5 — the one this whole rung exists for

Wrap the exact solution in a module with the operator's interface and push it through compute_i. If the residual does not come back at machine zero, something in the autograd path, the sign, ℓ, τ or the trunk layout is wrong — and you find it in seconds instead of after a training run.

class _Exact(torch.nn.Module):
    """Pretends to be the trained operator, returns the closed form."""
    F, max_freq, output_dim = 0, 0, 1          # F=0 -> trunk is raw t, channel 0
    def __init__(self, I, phi, r, B, wg, tau):
        super().__init__(); self.p = (I, phi, r, B, wg, tau)
    def forward(self, branch, trunk):
        I, phi, r, B, wg, tau = self.p
        t = trunk[..., 0:1]
        return I*torch.exp(r*t)*torch.cos(wg*t + phi) + B*torch.exp(-t/tau)

Two ways to fail T5 that look identical

A residual around 1e-4 relative means ℓ and τ are consistent but the derivative is off by truncation — check you are not differentiating numerically anywhere. A residual around 314× too large means an ω_b is missing again. And a residual that is exactly 2·R·B·h/ℓ means the B sign is back.

9.2 · rollout — where the operator becomes an integrator

This is the deployment mode: predict window 0, take your own prediction at the boundary as window 1's initial condition, repeat W times, then compare the stitched result against the true 0.5 s trajectory. One function does both arms: feedback=True chains its own predictions, feedback=False hands every window its true i₀ (teacher forcing).

Corrected — the handover is at t = S·dt, not at the last sample

An earlier version of this section handed over i_hat[:, -1]. That is the prediction at t = (S−1)·dt, one dt before the next window starts. On a 50 Hz carrier that is a slope error of ~ω·A·dt ≈ 1.9e-2 pu at every boundary. Measured on the same trained model: compounding 6.6× with the old handover, 1.57× with the correct one.

The fix is the t_ext trick from pll_infer.py: query the trunk at the S sensor times plus t = S·dt, hand over that extra point, and drop it before stitching. The trunk is continuous in t, so this costs one extra query point.

And the older trap still applies: the handed-forward i₀ must be re-normalised with the checkpoint's own i0_mean / i0_s_deviation before it re-enters the branch.

Update for Stage C: with trunk features up to 1 kHz, even this one-step extrapolation to t = S·dt goes wrong (19× the on-grid error). Stage C evaluation sets make neighbouring windows share their boundary sample instead — see §11.7.

    S = t.shape[0]

11.1 · One rule, one formula

Inductor current cannot step. Whatever a fault does to the voltages, the current moves continuously, and your supervisor's bound is that 1 pu takes at least 5 ms to disappear. So every "step" is a ramp. A fault is then fully described by two slow functions: the amplitude A(t) and the phase φ(t) of the current. Differentiate the carrier with the product and chain rules, exactly as in §1.3:

θ(t) = ω_g·t + φ(t) i = A(t)·cos θ di/dt = A′(t)·cos θ − A(t)·(ω_g + φ′(t))·sin θ └ amplitude moves ┘ └── the frequency is ω_g + φ′ while φ ramps ──┘ Δv = ℓ·di/dt + R·i ← get_delta_V, unchanged

Put A = I₀·e^(r t) and φ′ = 0 and this is the Stage A/B formula you already have. Nothing about the method changes; only the two functions get richer.

Stage B folds into this

I₀·e^(r t) with r up to 1.386/s doubles a 1 pu current to 2 pu — past any converter's current limit. A slow straight line from I₀ to I₁ over the whole 0.5 s does the same job and stays in range. It is just the drift event below.

11.2 · ramp — a straight line with rounded corners

Every event is built from one primitive: a ramp from 0 to 1. The obvious choice, a straight line with sharp corners, turns out to be the one choice that cannot work — the box below shows why, with numbers. So the ramp is straight in the middle, exactly as the supervisor and the wind-turbine paper describe a linear recovery, but its two corners are rounded over about 1 ms.

Measured: a sharp corner costs a factor of 10⁷

At a sharp corner di/dt jumps, so Δv jumps. The branch only sees Δv at the samples, and a jump makes what happens between two samples matter: the current after the corner depends on it, the samples do not show it. To measure the cost without training anything, fit the best possible linear map from the branch inputs to the current by least squares (T11 in §11.8) — a floor no linear branch can beat:

Build it the way you would sketch it — from the slope. The slope rises smoothly from 0 to 1/length over one corner, stays flat, and falls back over the other corner. A smooth 0 → 1 step is the raised cosine, so the slope is one step minus a later step, and the ramp is the integral of that:

x = clamp(t − s, 0, c) step(s) = (1 − cos(π x / c)) / 2 0 → 1 over [s, s + c] int(s) = x/2 − (c / 2π)·sin(π x / c) + max(t − s − c, 0) its integral, written out slope = [ step(start) − step(start + length) ] / length value = [ int(start) − int(start + length) ] / length → 1 once both corners have passed

The slope's own derivative is continuous too (sin is zero at both ends of a corner), so di/dt and Δv are smooth everywhere and the physics residual can be exactly zero at every sample. corner=0 gives back the sharp ramp, for the comparison.

def soft_step(t, s, c):
    """A raised-cosine step 0 -> 1 over [s, s + c], and its integral from -infinity to t."""
    x = (t - s).clamp(0, c)
    step = 0.5 * (1 - torch.cos(torch.pi * x / c))
    integral = x / 2 - c / (2 * torch.pi) * torch.sin(torch.pi * x / c) + (t - s - c).clamp(min=0)
    return step, integral


def ramp(t, start, length, corner=1e-3):
    """Straight 0 -> 1 ramp of slope 1/length, corners rounded over `corner` seconds.
    t (1,N); start, length (n,1). Returns value and its exact d/dt, (n,N) each."""
    if corner == 0:                                        # the sharp ramp, kept for the comparison
        inside = (t >= start) & (t < start + length)
        return ((t - start) / length).clamp(0, 1), inside / length
    step_a, int_a = soft_step(t, start, corner)
    step_b, int_b = soft_step(t, start + length, corner)
    return (int_a - int_b) / length, (step_a - step_b) / length

11.4 · Line_Simulator.multisine — white noise in Δv, made backwards

Why not add random numbers to Δv sample by sample

The exact response to per-sample (zero-order-hold) noise exists — i[k+1] = a·i[k] + (1 − a)·n[k]/R with a = e^(−dt/τ) — and it is a correct (Δv, i) pair. But that current has a kink at every sample, because Δv jumps at every sample. A smooth network cannot bend 125 times per window, and the physics residual at each sample would be off by about half the jump: Δn/(2ℓ) ≈ 11 pu/s for 0.005 pu of noise, against the 157 pu/s scale. The physics loss would sit near 5e-3 — 10⁴ times Stage A's — and fight the data.

Instead, build the noise from K random tones — a multisine, the standard system-identification excitation. With random frequencies across a band and random phases, the sum is statistically band-limited white noise. And each tone is a steady-state sinusoid, exactly like the Stage A carrier, so you already know its current: the tone's voltage divided by the line impedance at that frequency.

Δv_noise(t) = Σₖ v·cos(ωₖ t + ψₖ) v = σ·√(2/K) ← RMS of the sum is σ i_noise(t) = Σₖ (v/|Zₖ|)·cos(ωₖ t + ψₖ − ∠Zₖ) |Zₖ| = √(R² + (ωₖℓ)²), ∠Zₖ = atan(ωₖℓ/R) di_noise/dt = −Σₖ (v/|Zₖ|)·ωₖ·sin(ωₖ t + ψₖ − ∠Zₖ)

Band: 100 Hz – 1 kHz

Below it the line's admittance explodes: at DC it is 1/R = 200, so 0.005 pu of slow noise in Δv would push 1 pu through the line. Above 1 kHz the current response is tiny (|Z| > 2 pu) and the trunk would need Fourier features beyond 1 kHz.

Level: σ ∈ [0, 0.005] pu, per trajectory

About 5% of the ~0.1 pu steady Δv. Drawing σ per trajectory mixes clean and noisy data. 40 tones per trajectory is plenty to look like noise inside a 12.5 ms window.

This is noise the current really feels

The line responds to it, and the target current contains the response. That is not measurement noise, where the model should see a noisy Δv but predict the clean current — a different problem with a different answer. Question 6 for your supervisor.

    def multisine(self, sigma, f, psi, t):
        """Band-limited white noise in dv, generated backwards.
        sigma (n,1) noise RMS; f, psi (n,K) tone frequencies [Hz] and phases; t (1,N).
        Returns the current it drives and that current's derivative, (n,N) each."""
        ell, R = self.physics.Lc, self.physics.Rc
        w     = 2 * torch.pi * f                                   # (n,K)
        Z_mag = torch.sqrt(R**2 + (w * ell)**2)
        Z_ang = torch.atan(w * ell / R)                            # atan2 would need a tensor R
        c     = sigma * (2 / f.shape[1]) ** 0.5 / Z_mag            # current amplitude per tone

        i_n    = torch.zeros(f.shape[0], t.shape[1], dtype=torch.float64)
        didt_n = torch.zeros_like(i_n)
        for k in range(f.shape[1]):                                # a loop over K avoids an (n,K,N) tensor
            th = w[:, k:k+1] * t + psi[:, k:k+1] - Z_ang[:, k:k+1]
            i_n    += c[:, k:k+1] * torch.cos(th)
            didt_n -= c[:, k:k+1] * w[:, k:k+1] * torch.sin(th)
        return i_n, didt_n

The loop matters: 1000 trajectories × 40 tones × 5000 samples in float64 is 1.6 GB as one tensor, and 40 MB per tone.

        i, didt = sim.event_trajectory(p, t, corner=self.init_cond.stage_C.ramp_corner_ms * 1e-3)
        if self.noise:
            i_n, didt_n = sim.multisine(p["sigma"], p["f"], p["psi"], t)
            i, didt = i + i_n, didt + didt_n
        return i, didt, sim.physics.get_delta_V(i, didt)

    def build_event_set(self):
        C, S, N = self.init_cond.stage_C, self.S, self.sensors
        per     = C.windows_per_traj
        n_traj  = self.n_runs // per
        p = self.sample_events(n_traj)
        i, didt, dv = self.event_currents(p)

        # where each window starts: uniform, except a hot share placed over the onset
        starts = self._rng.integers(0, N - S + 1, size=(n_traj, per))
        n_hot  = int(round(C.hot_frac * per))
        onset  = np.maximum(p["ramps"][:, 0, 0], p["ramps"][:, 2, 0])      # amplitude or phase ramp; -1 if none
        hot_ok = onset >= 0                                                  # clean and drift have no onset
        hot    = np.clip(onset[:, None] - self._rng.integers(0, S, size=(n_traj, n_hot)), 0, N - S)
        starts[:, :n_hot] = np.where(hot_ok[:, None], hot, starts[:, :n_hot])

        idx  = torch.as_tensor(starts[..., None] + np.arange(S))         # (n_traj, per, S)
        rows = torch.arange(n_traj)[:, None, None]
        cut  = lambda x: x[rows, idx].reshape(-1, S)                       # (n_traj*per, S)
        i_w, didt_w, dv_w = cut(i), cut(didt), cut(dv)

        # a fresh homogeneous mode per window: moves i and i0, never dv
        tau = self.line_simulator.physics.t_constant
        h   = torch.exp(-self.line_simulator.t.double() / tau)                # (1,S)
        B   = torch.as_tensor(self._rng.uniform(*self.init_cond.ranges.beta, size=(n_traj * per, 1)))
        B   = B * p["I0"].repeat_interleave(per, dim=0)                       # relative to the level, as in Stage A
        i_w, didt_w = i_w + B * h, didt_w - (B / tau) * h

        records = {"i": i_w, "delta_v": dv_w, "di/dt": didt_w, "i0": i_w[:, 0],
                   "t_local": self.line_simulator.t.squeeze(0),
                   "event": p["event"].repeat_interleave(per),
                   "transition": self.in_transition(p["ramps"], starts, per),
                   "start": torch.as_tensor(starts.reshape(-1))}
        meta = {**self.build_meta(), "stage": "C", "noise": self.noise, "ramp_corner_ms": C.ramp_corner_ms,
                "events": EVENTS, "n_traj": n_traj, "stage_C": OmegaConf.to_container(C, resolve=True)}
        return records, meta

And the small helper both builders share — does a window overlap a fast ramp, corners included:

    def in_transition(self, ramps, starts, per):
        """ramps (n,3,2) sample intervals; starts (n, per) window starts -> (n*per,) bool."""
        r  = np.repeat(ramps, per, axis=0)                          # (n*per, 3, 2)
        st = starts.reshape(-1, 1)
        hit = (r[..., 0] >= 0) & (r[..., 0] < st + self.S) & (r[..., 1] > st)
        return torch.as_tensor(hit.any(axis=1))

Two intervals [a, b) and [c, d) overlap when a < d and c < b — that is the whole test. Drift never counts: its ramp is slow and spans every window, so sample_events leaves it out of ramps.

11.7 · build_event_trajectories — the evaluation set, with a shared boundary

Like your build_trajectories: 300 trajectories × 40 windows, seed + 10000, one trajectory-level B, run_id / segment_id so rollout can chain them, plus event and transition per window. And one real change: consecutive windows share their boundary sample — window k+1 starts on the last sample of window k (stride S − 1, not S).

Measured: the handover point must be a training point

Today window k+1 starts one dt after window k's last sample, so the handover queries the trunk at t = S·dt — a time it never saw in training (the t_ext trick, §9.2). With the Stage A trunk (Fourier features up to 100 Hz) that one-step extrapolation is harmless. With the features Stage C needs (up to 1 kHz) it is not:

T11 is new, and it is the most useful thing in this section. It is ten lines of numpy, runs in two seconds, and splits every future disappointment into one of two kinds. If a trained model sits far above the floor, the problem is optimisation — epochs, patience, learning rate, trunk features. If it sits near the floor, no amount of training will help; the data or the branch inputs have to change. That is exactly how the sharp-corner problem above was found.

def linear_floor(records, val_frac=0.15, seed=0):
    """Best any linear branch could do on these windows: least squares, scored on held-out rows."""
    X = np.c_[records["i0"].numpy(), records["delta_v"].numpy(), np.ones(len(records["i0"]))]
    Y = records["i"].numpy()
    perm = np.random.default_rng(seed).permutation(len(X))
    n_val = int(round(val_frac * len(X)))
    val, train = perm[:n_val], perm[n_val:]
    beta, *_ = np.linalg.lstsq(X[train], Y[train], rcond=None)
    return float(((X[val] @ beta - Y[val]) ** 2).mean())             # same units as val MSE(i)

It works on the records straight from build_event_set, or on a file from load_dataset. Put the result in the record next to val_i and you always know how far from the ceiling a run is.

11.9 · Scoring per event — metrics_by_event

One number over all events hides everything that matters here: a model can be excellent on the 10% of clean trajectories and bad on dips. Report one chained error per event type (the way the PLL's F32 split clean / sag / jump), and split the per-window error into windows that overlap a fast ramp and steady ones — that is where a fault's difficulty shows.

def metrics_by_event(model, ck, traj, W, events, shared_boundary=False, device="cpu"):
    S = ck["t_local"].shape[0]
    truth    = traj["i"].float().view(-1, W, S).to(device)
    chained  = rollout(model, ck, traj, W, feedback=True,  device=device, shared_boundary=shared_boundary)
    assisted = rollout(model, ck, traj, W, feedback=False, device=device, shared_boundary=shared_boundary)

    run_err = (chained - truth).pow(2).mean(dim=(1, 2)).sqrt()          # (R,)  one per trajectory
    run_ev  = traj["event"].view(-1, W)[:, 0].to(device)                  # one event per trajectory
    out = {f"chained_{name}": float(run_err[run_ev == k].mean())
           for k, name in enumerate(events) if (run_ev == k).any()}

    win_err = (assisted - truth).pow(2).mean(dim=2).sqrt()              # (R,W)  operator alone
    moving  = traj["transition"].view(-1, W).bool().to(device)
    out["assisted_transition_windows"] = float(win_err[moving].mean())
    out["assisted_steady_windows"]     = float(win_err[~moving].mean())
    return out
